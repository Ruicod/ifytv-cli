# IFYTV 云画布接口变更单

本单定义服务端目标契约。开发版 CLI 已接入整集计划、查询、报价和恢复。其余新增和扩展接口按服务端分级建设。既有契约见 [整集媒体](cli-production-api.md) 和 [云画布续做](cli-canvas-resume-api.md)。Dev 测试站点的匿名整集查询返回 HTTP 404。设备授权后的路由可用性、完整出片与计费未验证。

## 公共约定

- 类型中的 `!` 为必填，`?` 为可选。`uuid`、`int`、`str`、`bool`、`enum[…]`、`array<T>` 分别为 UUID、整数、字符串、布尔、枚举和数组。`sha256` 是 64 位十六进制。响应中没有数据时数组返回 `[]`。
- 原站点设备 Bearer 负责身份。工作区、项目权限、素材关联、视频/图/配音权限和计费主体由服务端解析。查询每次检查读取权，写入及重放每次确认写权。拒绝请求也不暴露他人资源。旧视频 Key 继续支持已授权的视频功能，设备权限由现有授权页授予。
- 新式改状态或计费请求需要 `Idempotency-Key`。旧 multipart 上传继续允许省略该头，旧 `/videos` 按项目和原任务去重。在身份、项目或工作区、操作命名空间下保存规范请求摘要与响应。随机键由旧 CLI 继续支持。新客户端在首个整集计划或恢复请求前保存其 `request_id`（UUID）和请求摘要。该 UUID 就是 `Idempotency-Key`，与操作名一起索引到回执。相同键和规范内容回同一 run、任务、资产或卡。不同内容回 `409 idempotency_conflict`。规范摘要使用素材内容和有序槽位，忽略暂存 URL 的变化。回执寿命覆盖用户能恢复的项目制作周期，不随上传过期。
- 先授权并查幂等回执，再检查修订号、预算和当前卡状态，再事务内领占用、保存回执和预扣，按可重放 outbox 驱动 worker。供应商侧接受标识或可核对的请求 ID 一并持久化。上游受理未知时进入 `uncertain`，等待查询或人工对账。只有确认没有提交时才允许重新尝试，禁止靠 worker 超时重发新的付费请求。任务回写持有节点租约与 fencing token，只更新其已领取字段。用户改了受保护字段时留存输出为候选并暂停采用。
- 错误统一为 `{"error":{"code":"…","message":"…","retryable":false,"request_id":"…","details":{}}}`，仅返回脱敏业务字段。HTTP 429/503 要提供 `Retry-After`。旧 CLI 可继续只解 `code` 和 HTTP 状态。

## 开发版命令

使用原站点、设备批准和项目权限。下列变量取自计划或真实回执，`PROJECT` 可为 UUID 或同站画布链接。`REVISION` 取自快照或运行回执，保留完整整数。`PLAN` 是本地 UTF-8 的 `EpisodePlan` JSON 文件。为计划与每次恢复分别生成并保存一个 UUID。

```sh
ifytv episode plan --project "$PROJECT" --revision "$REVISION" --spec "$PLAN" --request-id "$PLAN_REQUEST" --authorization-id "$AUTH" --json
ifytv episode status --project "$PROJECT" --episode-id "$EPISODE" --authorization-id "$AUTH" --json
ifytv episode status --project "$PROJECT" --run-id "$RUN_ID" --authorization-id "$AUTH" --json
ifytv episode status --project "$PROJECT" --request-id "$RESUME_REQUEST" --operation resume --authorization-id "$AUTH" --json
ifytv episode quote --project "$PROJECT" --run-id "$RUN_ID" --plan-hash "$PLAN_HASH" --step-id "$STEP" --authorization-id "$AUTH" --json
ifytv episode resume --project "$PROJECT" --run-id "$RUN_ID" --revision "$REVISION" --plan-hash "$PLAN_HASH" --request-id "$RESUME_REQUEST" --quote-id "$QUOTE_ID" --currency "$CURRENCY" --budget-units "$BUDGET_UNITS" --step-id "$STEP" --authorization-id "$AUTH" --json
```

查询可省略 `--episode-id` 列出项目内的整集。列表和指定 `--run-id` 的详情均可传上一页的 `--cursor`。按键查受理结果使用原 `--request-id` 和 `--operation plan|resume|render|publish`。报价和恢复可重复传 `--step-id` 指定多个步骤，省略时由服务端解析未完成步骤。恢复可传 `--quote-id`。传入新的预算时必须同时给该报价 ID、站点币种代码和非负整数额度，单位以站点为准。单条运行在 `episode_run`，列表和按键查询在 `episode_runs`，报价在 `episode_quote`。

同一设备重跑时，已知受理的键读取原运行。回执未落盘则先按键查证，默认同键不再提交 POST。`uncertain` 保留原项目、键和请求，继续查证。仅当原操作仍获授权，包括可能的首次付费，才可用 `episode plan` 或 `episode resume` 加 `--replay` 发送原键和原请求体。`not_accepted` 表明键已封闭。核对计划、费用与授权后，才可为新操作生成新键。待核实的云端操作不得回退为旧方式建单。服务端能力不足时保留现有进度和原请求 ID。

## 共用结构与合法流转

| 结构 | 字段与约束 |
| --- | --- |
| `EpisodePlan` | `episode_id:uuid!`、`plan_version:int!`（正数）、`ratio:enum[9:16,16:9]!`、`scenes:array<Scene>!`、`entities:array<Entity>!`、`shots:array<Shot>!`、`steps:array<ProductionStep>!`。`Scene` 为 `scene_id:str!`、`order:int!`、`script:str!`。`Entity` 为 `entity_id:str!`、`kind:enum[character,location,prop]!`、`version:int!`、`baseline_asset_ids:array<uuid>!`、`voice_id:str?`、`description:str!`。`Shot` 为 `shot_id:str!`、`scene_id:str!`、`order:int!`、`duration_ms:int!`、`description:str!`、`target_node_id:str?`、`reference_bindings:array<Binding>!`、`lines:array<Line>!`、`generation_spec:object?`。编号唯一，依赖无环。`Line` 为 `line_id:str!`、`character_id:str!`、`text:str!`、`start_ms:int!`、`end_ms:int!`、`voice_id:str?`、`audio_asset_id:uuid?`。 |
| `ProductionStep` | `step_id:str!`、`kind:enum[image,speech,video,render,publish]!`、`depends_on:array<str>!`、`entity_id:str?`、`shot_id:str?`、`line_id:str?`、`config:object!`、`output_slots:array<str>!`。生图 `config` 固定模型、画幅、提示词和引用；语音绑定实际音色和对白 ID；视频绑定镜头与模型设置、`dialogue_mode:enum[native,reference_audio,external_track]`；需要口型处理时明确要求支持该能力。渲染与发布显式依赖已采用结果。服务端按该能力版本校验 `config`，拒绝无效依赖和重复写卡。 |
| `Binding` | `entity_id:str!`、`version:int!`、`kind:enum[image,speech,video]!`、`slot:int!`（同类型内从 1 开始）、`asset_id:uuid?`、`from_step_id:str?` 和 `output_slot:str?`。资产 ID 与步骤输出二选一，选步骤时两个字段均必填。解析后核对真实资产、校验和、权限和输入顺序。多个引用同一角色时复用已接受版本。 |
| `Run` | `run_id:uuid!`、`episode_id:uuid!`、`plan_version:int!`、`plan_hash:sha256!`、`project_id:uuid!`、`revision:int!`、`status:str!`、`next_action:object!`、`steps:array<Step>!`、`billing:object!`、`artifact:object?`、`next_cursor:str?`。尚无步骤或账目时分别返回 `steps: []` 和 `billing: {}`。`succeeded` 必须带 `artifact`，包含 `node_id:str!`、`asset_id:uuid!`，可附 `sha256`、`duration_ms`。步骤有 `step_id`、`kind`、`shot_id?`、`node_id?`、`task_id?`、`attempt:int`、`status`、`output_asset_ids[]`、`error?`。`next_action.type` 为 `execute`、`poll`、`reconcile`、`authorize`、`fix_input`、`review` 或 `done`，可附 `step_ids[]`、`poll_after_seconds`。 |
| `Job` | `task_id:uuid`、`status`、`kind:enum[image,speech,video,render,quality]`、`phase?`、`progress?:int`（0–100）、`error_code?`、`node_id?`、`assets[]`、`billing_status?`。成功仅在成品持久化后公布。 |
| 整集状态机 | `planned → running` 或 `blocked`。`running → blocked`、`succeeded`、`failed` 或 `canceled`。`blocked → running` 或 `canceled`，需排除阻塞或批准后恢复。整集终态不可逆，同次运行重读返回原结果。只有整集媒体持久化且画布发布回执完成才是 `succeeded`。发布失败保留原渲染，运行进入 `blocked`。修订后新版本仅复用规范输入摘要相同且输出仍可访问的成功步骤。取消先停止安排新步骤，已受理项保留任务与计费对账，可继续在取消运行中查询。 |
| 步骤与任务状态机 | `queued → submitting → running → saving → succeeded`。发生确证错误时允许活动阶段到 `failed`。`submitting/running → uncertain` 时只对账，再回 `running` 或走 `saving/failed`。只有可证明未提交的 `queued/submitting` 可转 `canceled`。上游实际取消时允许 `running → canceled`。生产步骤还可为 `waiting_dependencies`、`blocked` 或 `reused`，这些状态不创建 Job。复用保留原任务与资产。等待超时只出现在客户端响应。 |
| 上传状态机 | `staged → attached` 或 `expired`，附件绑定任务或生产记录后，临时 URL 到期不改变已接收任务。 |
| 计费状态机 | `reserved → charged/released/uncertain`，`uncertain → charged/released`，已扣后的退款记 `refunded` 并给原流水。预算校验以整数最小单位与币种处理，含已结算、预扣和未明确金额。当上界无法证明时拒绝硬预算内的新建。 |

| `POST /api/v1/cli/projects/{project_id}/production-runs/{run_id}/renders`；`GET /api/v1/cli/projects/{project_id}/production-runs/{run_id}/renders/{render_id}`；`GET /api/v1/cli/projects/{project_id}/production-runs/{run_id}/renders/{render_id}/download` | 依据有序已采用片段和持久音轨渲染。`plan_hash:sha256!`、`clips:array<{shot_id,asset_id,in_ms,out_ms}>!`、`audio_tracks:array<{asset_id,start_ms,end_ms,role}>!`、`captions:array<{text,start_ms,end_ms}>!`、`format:enum[mp4-h264-aac]!`。可在 `resume` 的末步骤由 worker 创建。 | `render_id`、`Job`，成功时 `asset_id`、`sha256`、`duration_ms`。下载完整 MP4。 | 按任务状态机。按运行和规范时间线摘要去重。渲染重试排除上游图、音、视频任务。 | `render_input_missing`、`timeline_invalid`、`output_format_unsupported`、`render_failed`。 | 保留本地 `episode export`。已存在的用户编辑轨仅在本次请求授权范围内使用。 |
| `POST /api/v1/cli/projects/{project_id}/media/episodes` | 回写云画布成片。旧 `title:str!`、`video_url:str!`、`video_sha256:sha256!`。新版允许用 `render_id:uuid` 替换 `video_url`，可带 `run_id`、`expected_revision`、`target_node_id`。同一计划有明确成片卡时更新原卡。 | `project_id`、`node_id`、`asset_id`、`duplicate`，返回已落地的项目媒体，刷新可播放。 | 任务 `saving → succeeded`，发布回执独立于上传。相同运行版本与摘要复用同一成片卡。 | `canvas_revision_changed`、`canvas_node_not_resumable`、`canvas_asset_daily_limit`、`idempotency_conflict`。 | 保留旧完整 MP4 上传回写和 `publish_episode`。方案上线后逐步支持传渲染回执，旧客户端无需改变。 |

按键查询的 `receipt.request_sha256` 使用服务端首次受理的原始 JSON 请求体字节计算 SHA-256，摘要输入限于请求体。客户端用本机待确认记录核对该摘要。服务端原有规范化参数摘要另行存储，并继续用于幂等判定。回执的操作、请求键和运行 ID 必须与所查对象对应。
